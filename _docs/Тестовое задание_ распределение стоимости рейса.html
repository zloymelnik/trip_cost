Тестовое задание

Доработайте небольшую систему учёта рейсов: новый расчёт долей клиентов, API, блок в карточке рейса и экран пересчёта счетов. Работа с ИИ-агентом обязательна, инструмент выбирайте сами.

📘 Контекст

Компания перевозит сборные грузы: в одной машине едут грузы разных клиентов. Стоимость рейса компания делит между клиентами, и раз в месяц по этим долям выставляет каждому клиенту счёт. Бухгалтер формирует черновики счетов за месяц, проверяет их, отправляет клиентам и затем выгружает в 1С.

Сейчас стоимость делится по весу груза. Финансовая служба решила перейти на деление по объёму: клиенты с лёгким объёмным грузом (чипсы, хлеб, упаковка) занимают полмашины, а платят копейки.

Вам дан стартовый проект, небольшая система в стиле нашей основной (PHP без фреймворка, SQLite, jQuery). В нём есть журнал рейсов, карточка рейса, счета клиентов, отчёт о загрузке машин и выгрузка счетов в 1С.

  • Стартовый проект: trip-cost-starter.zip
  • Окружение: PHP 8.2+ с расширением pdo_sqlite. Composer можно подключить по желанию.
  • Как запустить, написано в README проекта.

⚙️ Функциональные требования

  1. Расчёт долей рейса
    • Стоимость рейса делится между клиентами пропорционально объёму их груза в рейсе (м³).
    • Сумма долей по рейсу совпадает со стоимостью рейса до копейки. Сейчас бывает расхождение на 1-2 копейки, и бухгалтерия правит счета руками.
    • Повторный расчёт на тех же данных даёт тот же результат.
  2. API долей рейса
    Метод: GET /api/trip_split.php?trip_id=11
    Пример ответа: 
    {
  "trip_id": 11,
  "number": "МСК-1111",
  "cost": "48750.50",
  "clients": [
    { "client_id": 1, "name": "ООО «Хрустим»", "cargo_count": 2,
      "weight_kg": 120, "volume_m3": 8, "share": 0.8, "amount": "39000.40" },
    { "client_id": 2, "name": "ООО «Родник»", "cargo_count": 1,
      "weight_kg": 2000, "volume_m3": 2, "share": 0.2, "amount": "9750.10" }
  ]
}
    • Если рейс не найден, метод отвечает 404.
    • Можно добавить свои поля, если они нужны экрану.
  3. Блок «Распределение стоимости» в карточке рейса
    • В карточке рейса (public/trip.php) нужна таблица по клиентам: клиент, число грузов, вес, объём, доля в процентах, сумма.
    • Итоговая строка: сумма по клиентам и стоимость рейса.
    • Блок получает данные из API. Фронт на jQuery, как в остальном проекте.
  4. API счетов за месяц

    Сейчас счета за месяц формирует кнопка «Сформировать счета за месяц» на странице счетов (public/billing_run.php). Она сразу пишет в базу. Нужны два метода: сначала посмотреть, что изменится, потом применить.

    Предпросмотр, ничего не меняет в базе: GET /api/billing_preview.php?period=2026-10
    Пример ответа (числа условные): 
    {
  "period": "2026-10",
  "clients": [
    { "client_id": 1, "name": "ООО «Хрустим»", "invoice_id": 41,
      "before": "18200.00", "after": "31450.75", "diff": "13250.75" },
    { "client_id": 3, "name": "ООО «Молочный двор»", "invoice_id": 42,
      "before": "52400.00", "after": "39149.25", "diff": "-13250.75" }
  ],
  "total_before": "70600.00",
  "total_after": "70600.00"
}
    Применение: POST /api/billing_apply.php period=2026-10
    • Формирует счета периода по новому правилу: создаёт недостающие, пересчитывает существующие.
    • Повторный вызов с тем же периодом не меняет данные и не создаёт дублей.
    • В ответе метод сообщает, что изменено.
    • Можно добавить свои поля, если они нужны экрану.
  5. Экран «Счета за месяц»
    • Новая страница public/billing.php, ссылка в меню.
    • Выбор месяца → кнопка «Показать» → таблица «было / стало» по клиентам: сумма сейчас, сумма по новому правилу, разница, итоги.
    • Кнопка «Применить» спрашивает подтверждение. После применения пользователь видит, что изменилось.
  6. Октябрь 2026
    • Счета за октябрь сформированы по старому правилу. Бухгалтерия закрывает месяц. Пересчитайте октябрь по новому правилу через новый экран.
    • Приложите к README, что показал экран после применения октября: таблицу или скриншот.
